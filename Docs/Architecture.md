# Architecture

Mechanics per system, as built. Read the relevant section before changing a system, and keep it current. Planned work for later phases is in `Docs/Ontwerp-Gevecht.md`.

## Combat (phases 1–5)

Code: `Source/BattleSystem/{Public,Private}/Combat/`. Layers: grid ← simulation ← presentation. Only the presentation layer touches actors during a fight.

### Grid

- `FCombatGridData` (plain struct) holds the size, cell size and per-cell `ECombatCellFlags` (`Blocked`, `BlocksSight`). Positions are **grid-local cm**: (0,0) is the corner of cell (0,0). Out-of-bounds cells are not walkable and block sight.
- `ACombatGrid` (placed in the level) owns a `FCombatGridData`. Its actor location is the grid origin. Rotation and scale are ignored. The floor is the engine plane, scaled in `OnConstruction`.
- Without a level the grid shows its own empty `Width` x `Height` (`GetGridData()`). Fights always come from a level, whose grid (`FCombatLevel::ToGridData`) holds the blocking of its pieces; the arena only gives the origin. (Until 2026-10-06 fights could also come from a `UCombatSetup` on the arena's own grid with placed `ACombatObstacle`s; both are gone.)
- **Edge walls**: walls on the border between two cells, stored as two bits per cell in `Edges` (`EdgeWest`: the border with X−1, `EdgeNorth`: with Y−1; empty while there are none). `AddEdgeWall(A, B)` / `HasEdgeWall(A, B)` take two orthogonal neighbors inside the grid (other pairs and the outer border are ignored; the outer border already blocks). An edge wall blocks walking and sight. `ComputeChecksum` adds the edges only when there are any, so checksums of grids without edge walls (and older replays) stay the same.
- `CanStep(Cell, Offset)`: the target cell must be walkable and no edge wall may be in between; a diagonal step needs both L-shaped routes open, cells and edges (no corner cutting). `NeighborOffsets` fixes the neighbor order for all searches.
- `IsLineClear(From, To, IsCellClear)`: a grid traversal (Amanatides & Woo) over every cell the segment crosses. It also fails on the first crossed border with an edge wall. Passing exactly through a corner needs both side cells clear and no edge wall on either route around it. `CrossesNoEdgeWall(From, To)` runs it with every cell clear (edges only); `ResolveMove` (its cell part `ResolveMoveInCells`) accepts a position only in a walkable cell reached without crossing an edge wall, otherwise it slides on X, then Y.
- **Wall clearance**: `PushClear(Position, Clearance)` pushes a position out to `Clearance` from unwalkable cells (also outside the grid) and edge walls within reach, in one pass in a fixed order (cells row by row, then edges). After the cell part, `ResolveMove` applies it with `min(unit radius, WallClearance)` and keeps the pushed position only if it is still a valid move. With clearance a unit's own move and the push from other units are resolved one after the other (`Moved = ResolveMove(Prev, Prev + Move)`, then `ResolveMove(Moved, Moved + Separation)`), so a push into a door frame cannot cancel the move; without clearance they are added and resolved together, as before. Steering (straight at the target, route lookahead from the distance map or A*, move orders) checks `IsSteerLineClear`: with clearance `IsWideLineWalkable` (the center line and lines 90% of the clearance to either side), else `IsLineWalkable`, so a unit does not aim past a door frame it cannot pass. Whether a melee attack may start still uses the thin line. `WallClearance` (45 cm, Project Settings > Combat > Movement; below half a cell so every unit fits through a one-cell opening) is in `FCombatSimSettings`: replays saved before it have 0 and so play exactly as recorded. It checks the center line only; unit radius is ignored until the clearance work in phase 6. `IsLineWalkable` uses it with walkable cells (melee, movement), and `HasLineOfSight` uses it with cells that don't block sight (ranged, projectiles). A sight-only obstacle (`bBlocksWalkability` off) therefore blocks shots but not walking.
- With `bDrawDebugCells` on, the grid draws persistent debug lines and red boxes for blocked cells at BeginPlay.

### Navigation layer (`CombatNavigation`, `CombatNavigation.h`, phase 6)

- Routes run on a finer grid than movement: every cell is split into `Subdivision` x `Subdivision` sub-cells (fixed 3, so 33.3 cm with 100 cm cells), one **nav grid** per clearance class. Movement, `ResolveMove`, `PushClear` and all line checks stay on the combat grid.
- **Clearance class** of a unit (`GetClearanceClass`): its radius rounded up to the distances at which sub-cell centers lie from a cell border, (class + 0.5) sub-cells, capped at `MaxClass` = 1 (50 cm) so every unit fits through a one-cell door (the user's choice; bigger units use class 1 too). So: radius up to 16.7 cm class 0, above that class 1.
- `BuildNavGrid(Grid, Class)`: a sub-cell is open when its cell is walkable and its center is at least the class clearance (`GetClassClearance`) from every unwalkable cell (also outside the grid; distance to the cell's box) and every edge wall (distance to the border segment); equal counts as open. Every edge wall is copied onto the sub-cell borders along it, so `CanStep` never crosses it. In a one-cell door class 1 leaves the middle sub-cell open, class 0 all three.
- `FindOpenCell(Nav, Position)`: the sub-cell under a position, else the nearest open one within 3 rings (by distance to the position, the first in row order on ties). Units pushed against a wall stand in closed sub-cells; their routes start from (and enemies are found at) the snapped one (`FCombatSimulation::GetNavCell`; the cell under the position when nothing is open).
- The simulation collects the classes of all units and wave spawns at construction (ascending, `NavClasses`), builds a nav grid per class, and gives each unit its class index (`FCombatUnit::NavClass`). Distance maps are kept per team and class (`GetDistanceMap(Team, NavClass)`); A* paths (`Unit.Path`) and the map lookahead run on the unit's class grid. `PathLookaheadCells` still counts whole cells (x `Subdivision` sub-cells). A failed A* search is remembered (`NoPathStart`/`NoPathGoal`) and not repeated until either end changes sub-cell.
- Cost (measured): about 8x per tick compared with whole cells. `Combat.Batch 1000` of the former `DA_Setup_Test` took about 22 s (was 3.4 s); live fights stay well under 1 ms per tick.

### Distance map (`FCombatDistanceMap`)

- Multi-source Dijkstra over a grid (the simulation passes a nav grid), using `CanStep` with integer costs 10 (straight) and 14 (diagonal). Each cell stores the distance and the ID of the nearest source.
- The heap order is (distance, unit ID, cell index), and a cell is improved on a shorter distance or an equal distance with a lower ID. Equal routes therefore always go to the lowest ID.
- `GetNextCell` returns the neighbor (reachable with `CanStep`) with the lowest distance below the current cell's. The first in neighbor order wins ties.

### A* (`CombatPathfinding::FindPath`)

- Same grid rules and integer costs as the distance map, with an octile heuristic. The open list is ordered by (F, H, cell index), so equal routes always come out the same. It returns start..goal, or false when the goal is unreachable.

### Effects (`FCombatEffectList`, `CombatEffects.h`)

- `FCombatEffectStats`:
  - `EffectTag`: the identity for stacking.
  - `DurationTicks`.
  - `Stacking`: `Refresh` restarts the duration and takes the newest source; `Stack` does the same and adds a stack up to `MaxStacks`; `Ignore` keeps the existing effect.
  - `GrantedTags` and `BlockedByTags`.
- `Apply` refuses an effect if the unit's innate tags or any active effect's granted tags match its `BlockedByTags`. `Tick` counts all effects down and removes those at 0.
- Modifiers: `MoveSpeedMultiplier`, `DamageDealtMultiplier` and `DamageTakenMultiplier`, applied once per stack. `GetMoveSpeedMultiplier()` (and the others) multiply over the effects in order. Movement uses the move-speed factor. Damage is base × the attacker's dealt factor (at the moment it fires) × the target's taken factor (when it lands). Threat uses the final damage.
- `FindSourceOfTag` returns the source of the effect that grants a tag, choosing the most ticks left and then the lowest source ID. The checksum uses the source, attack and effect indices, never tag names (FName indices can differ between runs).

### Simulation (`FCombatSimulation`)

- Input is an `FCombatSimConfig`: the grid copy, `FCombatUnitSpawn`s (stats, team, start cell; unit ID = index), seed, tick rate, `MaxTicks`, `MaxFirstAttackDelayTicks`, `RetargetIntervalTicks`, `PathLookaheadCells`, `SeparationStrength`, and the threat settings: `ThreatDecayFactorPerTick` and `ThreatDecayAmountPerTick` (each tick threat = threat × factor − amount, which covers both half-life and linear decay), `ThreatThreshold`, `ThreatSwitchRatio` and `RetargetDistanceMargin`. The simulation never sees UObjects; `UCombatUnitDefinition::ToSimStats` converts seconds to ticks once.
- Stats: `FCombatUnitStats` has `Attacks` (`FCombatAttackStats`: range, damage, cooldown and windup in ticks, `bNeedsWalkableLine` for melee, `bNeedsLineOfSight`, `ProjectileSpeed` (0 = direct hit), `SourceIndex` into the definition, `ThreatMultiplier`, `Effects`, and for area attacks `AreaShape`, `AreaRadius`, `ConeCosHalfAngle`, `TelegraphTicks`, `bAffectsEnemies`, `bAffectsAllies` and `ImpactCue`). `IsTargeted()` = not `CircleAroundSelf`. `IsRanged()` = targeted and needs no walking line. `IsArea()` = has a shape. Innate `Tags` come from the definition. Each unit has one cooldown per attack (`AttackCooldowns`).
- `FCombatArea::Contains(Position, Radius)`:
  - `CircleAroundSelf`: the unit's edge within `Radius` of the attacker's center.
  - `CircleAtTarget`: the unit's edge within `Radius` of the center.
  - `Cone`: the unit's edge within `Radius` of the attacker's center, and the angle to the unit's center at most half the cone angle (a dot product against `ConeCosHalfAngle`).
- The constructor places units at their start-cell centers. It draws each unit's `FirstAttackDelayTicks` (0..Max) from the seeded `FRandomStream`, in ID order. This is the only randomness so far. It also collects the team values in order of first appearance; each team has one distance map towards its enemies.
- `Step()`:
  1. Copy `Position` to `PreviousPosition` for all units and projectiles, and set `bAnchored` (alive and winding up or locked, `WindupTicks > 0 || LockTicks > 0`). All decisions in this step read `PreviousPosition` and `bAnchored`, so the processing order cannot matter.
  2. For every living unit: tick its effects, and decay its threat. Entries at ≤ 0 or on dead enemies are removed.
  3. Rebuild the distance maps (per team and nav class) if `(Tick - 1) % RetargetIntervalTicks == 0` or a unit died in the previous step. The sources are the open sub-cells of all living enemies on that class's nav grid.
  4. `UpdatePendingAreas`: count telegraphed areas down. At 0 an area goes off (`ResolveArea`) using the positions at the start of this step. Areas placed during this step only start counting next step, so an area goes off exactly `TelegraphTicks` steps after it was placed. Then the due player commands run (see Player commands), and then the waves (`UpdateWaves`, only with waves; see Waves).
  5. Each living unit, in ID order (`UpdateUnit`):
     - Decrease every attack cooldown.
     - **Action lock**: a unit with `LockTicks > 0` (recovery after its attack, or stagger after a hit) counts it down and does not walk this step. It still runs `UpdateCombat` (targets, and it may start an attack), except with a move order, which waits until it is free.
     - `UpdateCombat` decides the desired move:
       - If the unit is winding up an attack: no move. When the windup reaches 0 and the windup target is still alive (or the attack is an area attack), `FireAttack` does one of three things (and `StartRecovery` then sets `LockTicks` to at least the attack's `RecoveryTicks`, from the next step on; also for attacks without windup and player abilities):
         - queues the hit (no projectile);
         - spawns a projectile at the unit (`ProjectileSpawned`);
         - for an area attack, `PlaceArea` fixes an `FCombatArea`: the target's position for `CircleAtTarget`, or the attacker's position and the direction to the target for `CircleAroundSelf` and `Cone`. Without a telegraph it goes off right away (`ResolveArea`). With one it becomes an `FCombatPendingArea` (`AreaTelegraphStarted`) and stays where it was placed.
         - `ResolveArea` emits `AreaAttackFired` (with the area and the cue). It then queues a hit for every living unit inside the area (`FCombatArea::Contains`) that the team flags allow (`bAffectsEnemies` / `bAffectsAllies`; allies include the attacker), in ID order. Line of sight from the area's center is checked if the attack needs it.
         Every queued hit carries damage, threat (damage × `ThreatMultiplier`) and the attack index.
       - Areas around the unit first (`FindReadyAreaAttack`, `CircleAroundSelf`: taunt, auras). One starts when it is off cooldown (no target, `TargetId` = `INDEX_NONE`) and an affected unit inside it either is an enemy it would damage or lacks one of its effects from this unit. It ignores the first-attack delay. Targeted AoE (`CircleAtTarget`, `Cone`) goes through `FindUsableAttack` like any other attack: it needs line of sight if `bRequiresLineOfSight` is set, otherwise a walking line like melee.
       - `UpdateTarget`: if the unit has `Status.Taunted`, the source of that effect becomes the target right away (`Taunt`). Otherwise `ChooseTarget` runs on retarget ticks (`(Tick - 1) % RetargetIntervalTicks == 0`), when there is no living target, or when a taunt has just ended. In order of priority, with hysteresis:
         1. **Threat**: the highest threat entry (lowest ID on ties) if it is ≥ `ThreatThreshold`. The current target is kept while its own threat is ≥ the threshold and the best is below current × `ThreatSwitchRatio`.
         2. **Visible** (units with a ranged attack): the nearest enemy that the longest ranged attack can hit now (`CanShootNow`). The current target is kept while it can still be shot.
         3. **Nearest**: the enemy recorded in the unit's cell of its team's distance map, or as the crow flies if none is reachable. The current target is kept unless the new one is more than `RetargetDistanceMargin` closer (as the crow flies).
         `TargetReason` stores which rule chose it.
       - `FindUsableAttack`: of the attacks that can reach the target now (reach ≤ range, walking line if melee, line of sight if needed; reach = `GetReach`, from the attacker's center to the target's edge, so the attacker's own radius adds nothing), take the one with the smallest range, regardless of its cooldown. If there is one: no move, and `TryStartAttack` counts down `FirstAttackDelayTicks` first. Then, once that attack's cooldown is 0, it emits `Attack` (with `AttackIndex`), sets the cooldown, and starts the windup (or fires right away if the windup is 0). Close up a mixed unit thus uses melee and waits for it, and further away it shoots.
       - Clear walking line but no usable attack: move straight at the target by at most `MoveSpeed * FixedDt`, stopping just inside the longest range that will work from there (ranged only counts with line of sight). So archers stop at range and don't kite.
       - No clear line: `FindRouteSteerPoint` steers along a route on the unit's nav grid for up to `PathLookaheadCells` cells (x 3 sub-cells). It steers to the farthest route sub-cell center that is in a clear line (the first step is always taken), so routes are smoothed.
         - If the team's distance map of the unit's class leads to this target (its nearest ID in the unit's sub-cell), the route follows `GetNextCell`.
         - Otherwise (threat, taunt, hysteresis), the unit uses its own A* path (`Unit.Path`) on its nav grid, recomputed when the unit's or the target's sub-cell changes.
         - Without a route it steers straight at the target.
     - `ComputeSeparation`: each living unit, ally or enemy, that overlaps (center distance < sum of radii) pushes by `overlap * 0.5 * SeparationStrength`, or `overlap * 1 * SeparationStrength` when the other one is anchored. An anchored unit is not pushed at all. Units exactly on top of each other split along X: the lower ID goes to -X. Two anchored units that overlap stay so until one is free.
     - `ResolveMove`: the new position is previous + move + push. If it lands in an unwalkable cell (blocked or out of bounds), the unit tries X only, then Y only, else stays. So units never end in a blocked cell.
     - `SteerPoint` stores what the unit steered at, for debugging.
  6. `UpdateProjectiles`, in spawn order:
     - If the target is dead, the projectile ends.
     - Otherwise it flies at the target's new position (homing) by `Speed * FixedDt`. If it reaches the target (distance − radius ≤ step) with line of sight, it queues a hit and ends.
     - If the step crosses a sight-blocking cell, it ends without a hit.
     - Each end emits `ProjectileEnded`; ended projectiles are removed.
  7. `ApplyPendingHits`, in three passes so the processing order cannot matter:
     1. Apply all damage (`Hit` events with the attack's cue, damage > 0 only; damage × the target's taken factor), adding threat on the source to the victim's list and setting its `LockTicks` to at least `HitStaggerTicks` (stagger; a new hit restarts it, it does not add up). The list holds at most 8 entries; when full, the lowest is replaced only by more threat.
     2. Apply the attack's effects to every hit target that is still alive (`EffectApplied` events), in hit order and then effect order.
     3. Mark every unit with HP ≤ 0 dead (`Death` events; its threat, effects and path are cleared, and the distance maps are marked dirty). Units that hit each other in the same step both die.
  8. Outcome (after `UpdateWaveClear`, only with waves): no team left → `Draw`, one team left → `TeamWon`, `Tick >= MaxTicks` → `TimeLimit`. While `HasWavesLeft()` (a wave still to start, or spawns still to come), the wave team counts as alive.
  9. Checksum: CRC32 over the tick and each unit's position, HP, target, attack cooldowns, windup attack, first-attack delay, windup, lock ticks, alive flag, target reason, threat entries and effects, plus each projectile's ID, position and target, and each pending area's ID, remaining ticks, center and direction. With waves also the waves started, the next wave tick and the number of pending spawns (without waves nothing changes, so old checksums hold).
- Events (`GetEvents()`) are valid until the next `Step()`.

### Waves (`FCombatSimConfig::Waves`)

- A wave is a list of `FCombatWaveSpawn`s (stats, cell, `DelayTicks` after the wave start). All spawns are on `WaveTeam` (1). The constructor adds `WaveTeam` to the teams (it needs a distance map even without units at the start) and sets `NextWaveTick` = `WavePauseTicks`.
- `UpdateWaves` (in the step, after the commands): when `Tick >= NextWaveTick`, `StartWave` starts the next wave (`WaveStarted` event). It puts every spawn of that wave in `PendingSpawns` at tick `Tick + DelayTicks`, and sets `NextWaveTick` to `INDEX_NONE` (wait for a clear). Then every due pending spawn becomes a unit, in the order the waves started and then the spawn order. That order gives the unit IDs (always appended). Each new unit draws its `FirstAttackDelayTicks` from the seed and gets a `UnitSpawned` event. After a spawn the distance maps are rebuilt right away, so the new units take part in the same step. A spawn on an occupied cell still happens; separation pushes the units apart.
- `UpdateWaveClear` (after the hits): when no wave is scheduled, a wave is left, no spawn is pending and no `WaveTeam` unit lives, then `NextWaveTick = Tick + WavePauseTicks`.
- `CallWave` command: starts the next wave right away, also during a running wave (waves overlap; the one after it again waits for a clear). It is rejected when no wave is left. `UnitId` is ignored (`INDEX_NONE`).
- `FCombatUnit::SourceIndex` is the index of what a unit was made from: its config `Units` entry, or `Units.Num()` + its index among all wave spawns (waves in order). The subsystem (unit types, actors) and the batch (per-type statistics) use it, because unit IDs of wave units depend on the fight.
- The pause comes from `WavePauseSeconds` (Project Settings > Game > Combat > Waves, default 5 s) through `FCombatSimSettings::WavePauseTicks`, so replays keep their own pause.

### Levels (`FCombatLevel`, `CombatLevel.h`)

- A level (made with the LevelDesigner) is readable JSON in `<Project>/Levels/<Name>.json` and goes into git.
  - Fields: `FormatVersion` (9; the files in `Levels/` are always at the current version, a format change converts them in the same commit and leaves no conversion code; missing fields load as their defaults, unknown ones are ignored), `Width` and `Height` (5–40), `CellSize` (100), `Units` (`Type` = row name in the unit table, `Team`, `Cell`, `Position`, `Rotation`), and `Waves` (each with `Spawns`: `Type`, `Cell`, `Position`, `Time` in seconds after the wave start, and `Rotation`).
  - `Position` of units and spawns (0..8, row by row, 4 = the middle) is where in its cell it starts: one of the 3x3 nav sub-cells (`CombatLevels::GetUnitPositionOffset`, a third of a cell per step). `BuildConfig` turns it into `FCombatUnitSpawn::StartOffset` / `FCombatWaveSpawn::Offset`, and the simulation starts the unit at the cell center plus that offset; setups and units in the middle have no offset, so their checksums did not change.
  - `Rotation` of units and spawns is a start pose in 1/32 turns (0..31, 11.25 degrees, 0 = facing +X; `CombatLevels::GetUnitYaw`). It is presentation only: not in the simulation config, so it never changes a fight or its checksum.
  - Every cell is open; only pieces block. `Normalize` clamps the size. `Resize` removes units, spawns and pieces outside the new size.
- **Pieces** (`FCombatLevelPiece`, `Pieces` in the JSON): `Id` (catalog id "Category/MeshName"), `Slot` (pieces only replace pieces of the same layer and slot: a wall (""), an opening ("Opening": window, door frame) and a door leaf ("Leaf") share a border), `Layer` (`ECombatPieceLayer`: Floor, Cell, Edge, Detail, Wall), `Cell`, `Rotation` (quarter turns; Detail: eighth turns, 45 degrees), `Size` (cells before rotation; Edge: X = number of borders; Detail: 1x1), `bBlocksWalking`, `bBlocksSight`, for details `Detail` (position X + Y x `DetailGrid` on the detail grid of its cell) and `DetailGrid` (positions per cell side, copied from the catalog so positions keep their meaning), `Color` (sRGB, default white; only used by tintable pieces, presentation only), and for wall items `Facing` and `Height` (below). Footprint and blocking are copied from the catalog when a piece is placed, so levels, fights, batches and replays never need the catalog.
  - Floor and Cell pieces cover `GetCells()`: `Cell` + the rotated size (X and Y swap on odd rotations). Edge pieces cover `GetEdges()`: on an even rotation the borders between rows `Cell.Y-1` and `Cell.Y` from column `Cell.X` on, on an odd rotation the borders between columns `Cell.X-1` and `Cell.X` from row `Cell.Y` on. Edge pieces may lie on the outer border (visual only there).
  - Detail pieces cover their cell (`GetCells`) and overlap only a detail at the same position (`GetDetailCenter`); several details share a cell.
  - **Wall items** (Wall layer: paintings, clocks, posters) hang on one side of a border line: `Facing` (quarter turns of the front, 0 = +X, 1 = +Y, 2 = -X, 3 = -Y; facing +-Y means the border between rows `Cell.Y - 1` and `Cell.Y`, facing +-X the border between columns `Cell.X - 1` and `Cell.X`), `Detail` (first position within the border of `Cell`, `DetailGrid` positions per cell, catalog default 4) and `Size.X` (positions covered, possibly over several borders of the line: `GetWallStart`, `GetEdges` gives the borders they touch), `Height` (center above the floor, cm) and `Rotation` (tilt in the wall, 1/32 turns, 11.25 degrees). They cover no cells and never block, so `ToGridData` ignores them. They overlap only items on the same side of the same line with overlapping positions. `PlacePiece` refuses one that is not supported (`IsWallItemSupported`: every border it touches has a wall, an Edge piece without a slot, and no opening); placing a border piece (an opening) and `Resize` call `RemoveUnsupportedWallItems`, and the LevelDesigner calls it in `RefreshDesignView`, so items go with their wall in the same undo step. `FindPieceUnder` takes, before the Cell piece, the wall item on the nearest border line within reach on the point's side over the point's position.
  - `PlacePiece` refuses a piece that does not fit (`IsPieceInBounds`) and otherwise removes the pieces of the same layer and slot it overlaps. `FindPieceUnder` prefers, within the Cell and Edge layers, a piece with a slot (on top) over one without, so move and erase take a door leaf before its frame. `FindPieceAt(Layer, Cell)` finds a Floor or Cell piece.
  - `ToGridData` starts from an open grid, first collects the borders of openings that block nothing (door frames): a wall (empty slot) on such a border adds no edge wall, so the frame is a passage; a leaf or a window there still blocks. Then it adds the flags of blocking Cell pieces and blocking details (their whole cell: the simulation has no sub-cells) and an edge wall per border of every Edge piece that blocks (walking or sight; door frames block neither).
- `CombatLevels::BuildConfig` makes a simulation config: the grid from the rows, and units and wave spawns through a resolver (type name → `FCombatUnitType`). Units and spawns of an unknown type or on an unwalkable cell are skipped with a warning; cells that only block sight are fine. Every wave is kept, also an empty one. `Time` is rounded to ticks. `OutTypes` is indexed by `SourceIndex` (units, then all spawns); `OutRotations` gives their start rotations in the same order (the subsystem keeps them as `SourceRotations`, so a level's units and wave spawns appear in their rotation). Units turn away as soon as they move or have a target.
- `FCombatFightSource` (subsystem) is a level (unset: no fight), plus for a replay its unit and skill rows (`Units`; unset = the project's tables). `BuildSimConfigFromSource`, `StartFightFromSource`, `RunBatchInWorld` and replays all take it. `ResolveSource(Name)` loads `Levels/<Name>.json` (also "Level: Name"; empty = `DefaultLevel`).
- Arena (`ACombatGrid::ApplyLevel`):
  - It resizes the floor and redraws the debug cells for the level. While the level has floor pieces, the grid's own floor sinks `PieceFloorDrop` (2 cm, on the grid actor) below Z = 0, so it does not z-fight with them and still shows where no floor piece lies.
  - It shows the pieces (`ShowPieces`): the mesh of each piece's catalog entry (the settings' `PieceCatalog`, default `/Game/Environment/DA_PieceCatalog`), one plain static mesh component per piece (no instancing: pack materials often lack the instanced-static-mesh usage flag and then render with the default material; UE batches equal meshes itself), placed by `CombatPieces::ComputeMeshTransform`: with `bScaleToFit` first scaled to the footprint (Edge: the length; Floor, Cell: X and Y; never the height), then the bounds centered on the footprint (Floor, Cell) or on the border line (Edge), the bottom on the floor, turned by `MeshYaw` + 90 degrees x rotation (details: 45), then moved by the entry's `Offset` (mesh axes). Details are centered on their detail position, never scaled, and stand on `FindDetailBaseHeight`: if the Cell piece in their cell has its mesh bounds (placed) under the detail's center, on its `SurfaceHeight` (-1 = the bounds' top, 0 = nothing on it), else on the floor. So a toy on a table's cell stands on the table, and one beside a small chair on the floor. Unknown ids and a missing catalog are logged and skipped.
  - Wall items are placed by `CombatPieces::ComputeWallItemTransform`: `MeshYaw` puts the mesh's width along X with its front facing -Y, then the tilt around the front axis, then the turn to its `Facing`; centered over its positions at its `Height`, set off the line by `FindWallSurfaceOffset` (the face of the walls it hangs on, from their placed mesh bounds) plus half its depth, then moved by `Offset`. Items reaching above `LowWallHeight` are attached to the walls they hang on (`FWallPiece::Attached`) and hidden while those are lowered.
  - **Walls Up / Cutaway / Down** (`ECombatWallMode`, key V and a control panel button, default Cutaway; presentation only). `ShowPieces` remembers every border piece reaching above `LowWallHeight` (40 cm, settings) with its full component, a low version (a cut wall: the same mesh with the same openings and everything above `LowWallHeight` cut off, `ComputeLowCutBox`; none for a piece wholly above it, such as a high window) that is hidden until lowered, and its full-height world bounds. Lowering swaps their visibility, so frames and windows are cut, not squeezed. Each subsystem tick (`UpdateWalls`, also without a fight) passes the camera location and, for Cutaway, a point `CutawayTargetHeight` (60 cm) above every visible unit actor and LevelDesigner preview; `ACombatGrid::UpdateWalls` lowers all walls (Down), none (Up), or those whose bounds the line from the camera to a target crosses (Cutaway), touching only components whose state changes. Windows, door frames and leaves are border pieces too. The low versions go through `CutWallCache`, so equal pieces are cut once; the log line counts them.
  - **Wall openings**: `ShowPieces` first places every piece, then gives each wall (Edge, empty slot) the cut boxes of the openings that share a border with it (`SharesBorder`): `ComputeCutBox` (the opening's cut box, `GetCutBox`: its mesh bounds or `bCustomCut` with `CutSize`/`CutOffset`, placed with its transform and made a cell deep on both sides of the border line) and `ToMeshSpace` (into the wall mesh's own space). A wall with cuts becomes a `UDynamicMeshComponent` (`MakeCutWall`): the static mesh copied (`CopyMeshFromStaticMeshV2`, section materials) with each box subtracted (`AppendBox` + `ApplyMeshBoolean`), the cut faces take the wall's first material and all get the UV of the wall triangle nearest the cut (the pack colors by a texture atlas; the box's own 0..1 UVs showed a rainbow over the whole atlas). Results are kept in `CutWallCache` by `MakeCutKey` (mesh + boxes rounded to millimeters), so a rebuild only cuts what changed; a log line gives the number of cut walls, cache hits and milliseconds. The GeometryScripting plugin is enabled for this. Packaged builds will need Allow CPU Access on the wall meshes.
  - **Preview cuts**: while an opening is previewed (Build Mode), `UpdatePreviewCuts` swaps the shown walls (`ShownWalls`) on its borders for cut versions with its box added, hiding the wall (full and low; `bPreviewHidden` keeps `UpdateWalls` off it); it recomputes only when the previewed opening's id, cell or rotation changes and restores the walls when the preview moves away or hides. The cuts go through the cache, so placing the opening afterwards reuses them.
  - `ClearLevel` goes back to the arena's own empty grid (leaving the LevelDesigner without a fight).
  - The subsystem points the view camera straight down with grid X (width) to the right and Y (height) downwards, like the rows of a level file. It fits it above the shown grid with a 12% margin, using its FOV and the viewport aspect, and puts the map's own camera back without a level. This "overview" is only shown again when its kind (level or none) or the grid size changes, or on F / Reset camera, so a camera the player moved stays (see the free camera below).

### Player commands (`FCombatCommand`, `CombatTypes.h`)

- A command is `Tick`, `UnitId`, `Type`, and either `TargetCell` (for `Move`) or `AbilityIndex` (for `Ability`). `CallWave` has no unit (see Waves). With the level, seed and settings, the command log determines the fight.
- Sources: `FCombatSimConfig::Commands` (a script or replay), queued in the constructor sorted by tick with the given order kept; or `QueueCommand` during the fight, which accepts only `Tick > GetTick()`. Every accepted command goes into `GetCommandLog()`.
- `ExecuteDueCommands` runs at the start of a step, after `UpdatePendingAreas` and before the units, in (tick, given order). `ExecuteCommand` emits `CommandExecuted`, or `CommandRejected` for a dead or unknown unit, a blocked or out-of-bounds move cell, or an unknown or non-area ability. Rejected commands stay in the log.
- `Move`: sets `bHasMoveOrder` and `MoveTargetCell`, and cancels a windup. While the order is active, `UpdateMoveOrder` replaces all AI. There is no targeting and no attacking, and taunts are ignored (the player's command wins). The unit steers straight when the line is clear, else along its own A* path (`SteerAlongPath`, on its nav grid to the open sub-cell at the middle of the order's cell). Within one step of the cell center it steps onto it and the order ends; an unreachable goal also ends it.
- `Ability`: uses `FCombatUnitStats::PlayerAbilities[AbilityIndex]` right away, without cooldown or windup, through `PlaceArea` (only `CircleAroundSelf` for now). The AI never uses player abilities. Attack indices run over `Attacks` and then `PlayerAbilities` (`GetAttack`, `GetPlayerAbilityAttackIndex`), so events, hits, effects and cues work the same.
- Checksum: a move order is hashed only while active. A fight without commands therefore has the same checksums as before commands existed, and old replays stay valid.
- Scripts: `UCombatCommandScript` (`Commands`; unit IDs = the order of the level's valid units, then wave spawns as they appear) for `Combat.Simulate ... script=<name>`, `Combat.Batch ... script=<name>` (the same commands on every seed) and the tests.

### Subsystem (`UCombatSubsystem`, game/PIE worlds only)

- `FCombatSimSettings` (`CombatReplay.h`) is every setting that changes a fight, in simulation units: tick rate, max ticks, first-attack delay, retarget interval, lookahead, separation, the threat factor/amount/threshold/ratio/margin, the taunt range override (also on wave spawns), and the wave pause. `FromProjectSettings(TauntOverride)` converts the project settings (seconds → ticks, half-life or linear → factor/amount). `ApplyTo(Config)` writes them into a config, including the taunt override on every Taunt skill.
- `BuildSimConfigFromSource(World, Seed, Source, Settings, ...)` builds the config with `CombatLevels::BuildConfig` and takes the origin from the world's first `ACombatGrid` (else (0,0,0)), then applies the settings. The panel starts fights with `GetCurrentSimSettings()` (the project settings plus the panel's taunt range); replays pass their own.
- `IssueCommand` (player input): only for units of `PlayerTeam` (`CallWave` needs no unit), not during a replay or after the fight. It sets `Tick` = current tick + `CommandDelayTicks` (3) and queues the command. This also works while paused (tactical pause); the command then runs 3 ticks after resuming.
- `CallWave()` sends a `CallWave` command; `CanCallWave()` is false when no wave is left or a call is already queued. `GetWaveText()` gives "Wave 2/4, next in 3.2 s" (or "next after clear", "spawning", "last wave"), empty without waves. `WaveStarted` logs and shows "Wave n/N" on screen.
- Checkpoints: after every step on a multiple of `ReplayCheckpointInterval` (20), the checksum is recorded. During a replay it is compared, and the first differing tick is remembered.
- `BuildSimConfigFromSource` takes the unit types from `FCombatFightSource::Units` (a replay's rows) or else from the project's tables: it copies the row of every type the level names, and the rows of its skills, into an `FCombatUnitCatalog` (`AddFromTables`). A type that is not in the unit table is skipped by `BuildConfig` (warning); a type that names a skill that is not in the skill table stops the fight (error). Every type is resolved once and shared by its units.
- `StartFight` replaces any running fight. It keeps the catalog (`CurrentUnits`, for replays), the types by `SourceIndex` (`SourceTypes`) and spawns one actor per unit (`SpawnUnitActor`): the row's `ActorClass`, or `ACombatUnitActor`, with its look (`InitLook`). On `UnitSpawned` it spawns the actor of a wave unit the same way. `UnitActors` and `UnitTypes` (per-skill presentation settings) stay indexed by unit ID; `GetUnitType` gives a unit's type to the UI.
- Projectiles: on `ProjectileSpawned` it spawns the skill's `ProjectileActorClass` (or `ACombatProjectileActor`), found through `FCombatAttackStats::SourceIndex`, into `ProjectileActors` (by projectile ID). On `ProjectileEnded` it destroys that actor. Every frame, projectiles are interpolated like units.
- `Tick`:
  - Add the engine DeltaTime × `TimeScale` to the accumulator, unless the fight is paused (`SetPaused`, `SetTimeScale`), and run up to `MaxStepsPerFrame` steps. Pause and speed only change when steps run, so the fight itself is unchanged. After each step, dispatch its events to the actors.
  - Clamp the accumulator to one step, so a backlog is dropped.
  - Push the interpolated state to the actors with alpha = accumulator / FixedDt. The facing is towards the target, otherwise along the velocity.
  - When the fight ends, log and show the result once.
  - `Combat.Debug` (console variable): `1` draws a line from each unit to its target in the team color, and a yellow line to its steer point when that is not the target. `2` also prints team 0's distance map (of the smallest nav class) per sub-cell (in sub-cells). The target line's color is the reason: team color = nearest, cyan = visible, orange = threat, magenta = taunt.
  - An `Attack` event without a target (area attack) gives the unit's lunge no direction.
  - Areas:
    - Telegraphs (`GetPendingAreas`) are drawn every frame as a `TelegraphColor` outline, with an inner outline that grows until the area goes off.
    - `AreaAttackFired` flashes the shape for `AreaPulseDuration`. The color comes from the cue's `DebugColor` in the cue table, else `TauntColor` for taunts, else `DefaultAreaColor`. The cue's Niagara system and sound play at the area's center, and the source actor's `OnAreaAttack` Blueprint hook is called.
    - Circles and cones are drawn from their center with `Radius` (every shape reaches from its center).
  - Cues: on a `Hit` of a non-area attack, the cue table entry for its `ImpactCue` plays at the hit unit. `UCombatCueTable` (`DA_CueTable`, set in settings `CueTable`) holds entries of cue tag, Niagara system, sound and debug color; everything is optional.
  - `Combat.ShowRanges` (console variable, also the panel's "Taunt range" button): a circle around every unit with an area attack, with radius `Range`. An enemy whose edge is inside the circle is hit.
- Replays (`FCombatReplay`, JSON through `FJsonObjectConverter`, in `Saved/Replays/<timestamp>_Level: <name>_<seed>.json`):
  - `SaveReplay` (only after the fight is over) stores the build version, a full copy of the level (so it does not depend on the level file), the unit and skill rows of the fight (`Units`, an `FCombatUnitCatalog`, so tuning the tables does not change it), the seed, the `FCombatSimSettings` used, the command log, the command delay, the checkpoints, and the recorded ticks, outcome and final checksum. Format version 7; older replays (which could come from a setup asset, named unit definition assets, had tags for skill types and slots, or had no recovery and stagger) are refused.
  - `PlayReplay` starts the fight with the replay's settings and commands (not the current ones) and warns about another build. Player input is ignored while it plays.
  - When the fight ends, `ReportResult` compares ticks, checksum and checkpoints and sets `GetReplayVerdict()` ("identical", or "DIFFERENT" with the first differing checkpoint tick).
  - The float settings survive JSON bit for bit (tested).
- Batch (`CombatBatch::Run`, `CombatBatch.h`):
  - It runs N copies of one config with seeds `StartSeed...` and collects, per fight, the seed, outcome, winner, ticks and checksum.
  - It also collects wins per team (in order of first appearance), draws and time limits, and per unit type (row name, by `SourceIndex`, so wave units count too) the units, damage dealt, damage taken and survivors. The simulation tracks `FCombatUnit::DamageDealt/DamageTaken` after the taken multiplier; they are not in the checksum.
  - `ToSummary` gives win rates, duration avg/min/max, and averages per unit. `WriteCsv` writes `<base>_fights.csv` and `<base>_units.csv` to `Saved/CombatBatch/`.
  - `RunBatchInWorld` builds the config once from the level; batch fights are exactly the single runs of those seeds (tested).
  - 1000 fights of the former `DA_Setup_AoE` (8 units) took ~3.4 s headless before the navigation layer; `WallWindows` (11 units, 2 waves) takes ~170 ms per fight.
- Console commands: `Combat.Start [seed]`, `Combat.Simulate [seed]` (headless; the subsystem's taunt override if there is a subsystem), `Combat.Stop`, `Combat.Batch <count> [startseed] [csv]`; these three take `level=<name>` and otherwise play `DefaultLevel`. An extra argument (an old setup name) is an error. Also `Combat.SaveReplay`, `Combat.Replay <file>`, and the player commands `Combat.Move <unit> <x> <y>`, `Combat.Ability <unit> [index]` and `Combat.CallWave`. Simulate and Batch accept `script=<name>` (found by asset name through the Asset Registry, or by object path).

### Presentation (`ACombatUnitActor`)

- Placeholder look: a body mesh (diameter = 2 × radius, height `BodyHeight`, 10 cm: flat pieces like on a board). It is `RangedBodyMesh` (default the engine cube) for units with a ranged attack and `MeleeBodyMesh` (default the engine cylinder) otherwise; the subsystem passes `bRanged` to `InitUnit`. The body has a dynamic material in the team color (made from `BodyMaterialBase`, default `BasicShapeMaterial`, through the `BodyColorParameter` `Color`; the cylinder's own `DefaultMaterial` has no color parameter), and a small cube "nose" for the facing. No collision.
- `OnAttack` lunges towards the target (sine over `LungeDuration`). `OnHit` flashes white and shows the damage as debug text. `OnDeath` shows "X" and hides the actor. Two screen-space `UWidgetComponent`s (Slate, built in code: `SCombatUnitWidgets`) show more:
  - **Health bar** (`SCombatHealthBar`), `HealthBarOffset` above the body and `HealthBarSize` pixels. The fill goes from green (full) via yellow (half) to red, and the rim has the team color. It uses its own `FProgressBarStyle` (plain white fill, dark background) because the default style tints the fill. Each frame the subsystem calls `SetHealth(HP / MaxHP)`.
  - **Status labels** (`SCombatStatusIcons`) on the body's center: one label per active effect, in effect order.
    - The label and color come from the `StatusIcons` setting (`Effect.Taunt` T magenta, `Effect.Slow` S cyan, `Effect.Rally` R yellow). An unlisted effect shows the first letter of its tag's last part, in white.
    - Stacks above 1 are added as a number (S2).
    - The row is only rebuilt when the labels change.
  Both are visible in release builds; they replace the old debug-text "T". `OnAreaAttack` is only a Blueprint hook (`On Unit Area Attack`); the subsystem draws the area. Each one also calls a Blueprint event (`On Unit Attack/Hit/Death`) for subclasses.

### Piece catalog (`UCombatPieceCatalog`, `CombatPieces.h`)

- A Data Asset of `FCombatPieceDefinition`s: `Id` ("Group/Sub/MeshName"), `MountHeight` (wall items: default center height, 150 cm), `bTintable` (the placed piece's `Color` tints it: `CombatPieces::ApplyTint` replaces every material slot with a dynamic instance of the settings' `TintMaterial` (default the engine's `BasicShapeMaterial`) with vector parameter `Color`; in the arena and the preview), `Category` (palette group "Group/Sub": the catalog folder), `Mesh`, `Layer`, `Size`, `bBlocksWalking`, `bBlocksSight`, `Slot`, `bCustomCut`/`CutSize`/`CutOffset` (openings: the box cut out of walls instead of the mesh bounds), `MeshYaw` (so the mesh's length lies along X), `bScaleToFit` (stretch or squeeze to the footprint, for shorter variants of a long mesh), `SurfaceHeight` (Cell pieces: where details stand on them), `Offset` and `DetailGrid` (Detail: positions per cell side, default 3). `MakePiece(Cell, Rotation)` makes a level piece with the footprint and blocking copied (floors never block).
- The catalog folder `/Game/Environment/Catalogus` has main categories with subcategories: `Building/` (`Walls`, `Windows`, `Doors`, `DoorLeaves`, `Floors`), `Furniture/` (`Chairs`, `Tables`), `Props/` (`Food`, `OfficeSupplies`, `Toys`) and `WallProps/` (wall items, one folder without subcategories). Large and small pieces share a subcategory; the LevelDesigner sorts them by size. `Scripts/RestructureCatalog.py` (one-off, editor closed) moved the old one-level folders there and renamed the piece ids in `Levels/*.json`.
- `Scripts/CreatePieceCatalog.py` creates or updates `/Game/Environment/DA_PieceCatalog` from `/Game/Environment/Catalogus/<Group>/<Sub>/` (local content, like the pack). Existing entries are kept; an entry whose mesh moved to another catalog folder keeps its tuning and gets that folder's category and id. New meshes get defaults from their bounds, by subcategory: everything under `WallProps` -> Wall item (width = the longer horizontal side in positions of 4 per cell, `MeshYaw` 90 when that is Y, `MountHeight` 150, never blocking; the front must face -Y after `MeshYaw`: a mesh whose depth lies on the positive side of its pivot (pivot on its back) gets 180 more; for one centered on its pivot the front cannot be told, so one hung back to front needs 180 more in the catalog; `WALL_FRONT_FLIPPED` lists the ones found in PIE so a rebuilt catalog gets them right); everything under `Props` -> Detail (1x1, `DetailGrid` 3, not blocking); Floors -> Floor, footprint in cells; Walls, Windows, Doors and DoorLeaves thinner than 50 cm -> Edge, length in cells along the long side (`MeshYaw` 90 when that is Y), Windows and Doors (frames) with slot "Opening", frames not blocking, DoorLeaves with slot "Leaf" and blocking walking and sight (a closed door); the slot per subcategory is also set on existing entries; everything else -> Cell, footprint in cells (at least 1), Walls blocking walking and sight, others walking. Entries whose mesh is gone from the catalog folder are removed. The entries are ordered by `CATEGORY_ORDER`. `VARIANTS` adds scaled-to-fit shorter versions of border pieces (`Building/Walls/SM_Walls_008_1m/_2m/_3m`), because the pack's walls are all 4 m long. `SOLID_FLOOR_SIZES` adds the solid floors `Building/Floors/SolidFloor_1x1` .. `_4x4`: the engine plane (`/Engine/BasicShapes/Plane`; its own material is `WorldGridMaterial`, which the tint replaces) scaled to fit, Floor layer, tintable; they are kept although their mesh is outside the catalog folder.
- `Scripts/MakeWallVariants.py` makes taller or lower copies of catalog meshes next to the source (`<mesh>_<height>cm`, a Z build scale on every LOD so the bounds are that tall; the texture stretches with it); its `VARIANTS` list holds source -> heights (now `Building/Walls/SM_Walls_007` -> 300). It must run in editor mode (`-ExecCmds="py <script>, QUIT_EDITOR"`), because the static mesh editor functions need an editor; an existing variant of another height is scaled to the right one. `CreatePieceCatalog.py` then adds the variants to the catalog.

### Character looks (`FCombatLook`, `CombatUnitData.h`)

- The modular look of a unit, a struct in its unit row (`FCombatUnitRow::Look`). Without slots the unit keeps the placeholder shape. Pure presentation: the simulation never reads it. Meshes are soft references (local content), loaded when the actor builds the look (`ACombatUnitActor::InitLook`); a missing mesh leaves its slot empty.
- **Slots** (`FCombatLookSlot`): a `Slot` (`ECombatLookSlot` in `CombatTypes.h`: `Body`, `Face`, `Hair`, `Hat`, `Glasses`, `Shirt`, `Outwear`, `Pants`, `Shoes`, `Gloves`, `Backpack`; a new slot is a code change; Python name `CombatLookSlotType`), a list of skeletal mesh `Options`, an `EmptyChance` and `bSwappable`. All meshes of a look must share one skeleton.
  - `PickMeshes(Seed)` picks per slot, in slot order, with its own `FRandomStream` (two draws per slot, so adding options to one slot does not change the picks before it). The subsystem passes `HashCombine(fight seed, unit ID)`, so a replay shows the same figures. One option = always that one.
  - Slots without `bSwappable` are merged into one skeletal mesh on `ACombatUnitActor::CharacterMesh` (`SkeletalMerging` plugin, `USkeletalMergingLibrary::MergeMeshes`). `UCombatMeshMergeCache` (`CombatMeshMergeCache.h`, a world subsystem, game and PIE worlds) keeps one merged mesh per combination of parts, so units with the same parts share it. A failed merge is cached as such and logged; the actor then shows every part as its own Leader Pose component.
  - Swappable slots are their own `USkeletalMeshComponent`s on `CharacterMesh` with Leader Pose, so they can change during play: `SetSlotMesh(Slot, Mesh)` (Blueprint-callable; a new slot is added, a merged slot is refused) and the debug command `Combat.SetSlot <unit> <slot> [mesh]` (the slot by name, `Hat`).
- **Overrides** (`FCombatLookOverride`): while the unit has `WhileTag` (an active effect's tag or a tag it grants, or an innate tag; parent tags match), a swappable slot shows `Mesh` (or nothing). The first matching override in the list wins. An override of a slot the look lacks gets an empty swappable slot; one of a merged slot is ignored with a warning. Each frame the subsystem passes the tags to `SetActiveTags`, only for actors whose look has overrides, and the actor only refreshes the slots when the tags change.
- **Props** (`FCombatLookProp`): static meshes on a socket or bone of `CharacterMesh`, with an offset. Works with meshes from any pack.
- **Shape**: `UniformScale`, `WidthScale` (X/Y) and `HeightScale` (Z) are the scale of `CharacterMesh`; parts and props follow it. `MeshRotation` (default yaw -90, for meshes that face +Y). The health bar and status labels are placed by the figure's height (the merged mesh's bounds × the Z scale) instead of `BodyHeight`.
- `AnimSet` (a `UCombatAnimSet`, see below; empty = reference pose). The body has `OnlyTickPoseWhenRendered`. With a look the hit flash does nothing (no team color material).
- Cooked builds: runtime merging needs "Allow CPU Access" on the source meshes.
- Parts made for other (adult) skeletons with the same bone names can sit in a **swappable** slot: Leader Pose maps the bones by name, so they follow the child's bones relative to their own skeleton's pose (in a merged slot they keep their adult height and float). They are still adult-sized: `Scripts/MakeChildHats.py` copies the hats `SK_Hat_*` of the Creative and Funny Characters packs to `/Game/Characters/Meshes/Child/Hats` (`SK_Hat_Creative_*`, `SK_Hat_Funny_*`) and fits every LOD with Geometry Script: scaled around the pack's adult `Head` bone by the child head's width and depth over the adult head's (vertices above `Neck` of `SKM_Hero` and of a pack body; Creative 0.69, Funny 0.48), then moved so the top and middle of the head match (Creative (0, -2.0, -4.4), Funny (0, -0.9, -1.4) cm). Skin weights, skeleton, UVs and materials stay; every run starts from fresh copies (`TUNE_SCALE` per pack for tuning by eye).
- The looks are in `Data/Units.json` with the rest of the unit (migrated on 2026-10-07 from the former `DA_Look_*` assets): Krijger, Boogschutter and Tank have fixed parts (Tank wider and taller), Brute has random parts and a bicycle helmet while `Status.Taunted`; Bijlman, Doelpop, Magier and Vaandeldrager have no look yet. `Scripts/CreateCharacterAnimSet.py` creates `DA_AnimSet_Child`.

### Character animation (`UCombatAnimSet`, `UCombatAnimInstance`, `CombatAnimation.h`)

- `UCombatAnimSet` (Data Asset, one per skeleton; `FCombatLook::AnimSet` points to it). Presentation only.
  - `AnimClass`: the AnimBP, with `UCombatAnimInstance` as parent. C++ only fills its inputs; the AnimGraph decides what to play (for example a state machine Idle <-> Locomotion on `bIsMoving`, a Blend Space Player on the `Locomotion` variable at (`LocomotionX`, `LocomotionY`) with Play Rate `LocomotionPlayRate`, then montages in its `DefaultSlot`). Inputs: `LocalVelocity` (cm/s relative to the facing: X forward, Y right; `ToLocalVelocity` from the world velocity and the actor's yaw), `Direction` (its angle, 0 forward, 90 right, +-180 back), `Speed` (its length, actual), `bIsMoving` (above `LocomotionMovingThreshold`, settings), `MoveSpeed` and `LocomotionRate` (from the unit definition, `SetTuning`), `SpeedRatio` (Speed / MoveSpeed), `SlowestSampleSpeed` / `FastestSampleSpeed` (the moving samples of `Locomotion` on its speed axis, read every frame so blend space edits count at once), `LocomotionPlayRate`, `MeshScale` (the look's, 1 without one), `StrideSpeed` and `bDead`. `SetLocomotion` finds the blend space axis named "Speed" (`FindSpeedAxis`; X if none) and `SetSpeed` puts the speed on that axis and 0 on the other, so one Template AnimBP works for every skeleton and blend space (`BS_Child_Idle_Run` has Speed on Y).
  - `Locomotion`: idle/walk/run blend space by speed in cm/s. Put the walk and run samples at the speed they really cover.
  - Axes by name (`FindAxis`, `GetBlendCoordinates`): a blend space with axes **Forward** and **Right** gets the local velocity (at the standard size) on them, so sideways and backwards steps blend; otherwise `StrideSpeed` goes on the axis named **Speed** (X if none). The AnimBP stays the same: `LocomotionX/Y` into the Blend Space Player. In a Forward/Right blend space a sample's speed (for the play rate) is its distance from the middle.
  - Size: `StrideSpeed` = `Speed / Lerp(1, MeshScale.Z, LocomotionScaleCompensation)` (`ComputeStrideSpeed`; settings, default 1), the speed at the standard figure size: a taller figure takes longer steps. `LocomotionX/Y` and the play rate use it; `bIsMoving` and `SpeedRatio` use the real `Speed`.
  - `LocomotionPlayRate` (`ComputeLocomotionPlayRate` on `StrideSpeed`, play-rate matching): 1 while standing still and between the slowest and fastest moving sample (there the blend space blends the stride); beyond them `Speed / that sample`; then times the definition's `LocomotionRate` (presentation, not in the fight) and clamped to `LocomotionMin/MaxPlayRate` (settings, 0.5..2).
  - `ACombatUnitActor::SetAnimationState` picks up a new anim instance (a recompiled AnimBP) or a swapped blend space and passes the tuning from `SetLocomotionTuning` (set at spawn from the unit row) every frame.
  - `Actions`: tag → montage. `FindMontage` takes the entry with the longest tag that the requested tag matches, so a tag without an entry falls back to its nearest parent (`Anim.Throw` → `Anim`). Entries without a montage are skipped.
  - `IdleBreaks` with `Min/MaxIdleBreakInterval`, `TurnRate` (deg/s, 0 = at once), `CorpseDuration`, `Min/MaxPlayRate`.
- Native tags `Anim`, `Anim.Hit`, `Anim.Death`, `Anim.Throw`, `Anim.Push`, `Anim.Punch`. `FCombatSkillRow::AnimationTag` (presentation; not in the simulation stats) picks a skill's montage; empty = no montage (the body lunges). `UCombatSubsystem::GetAttackAnimationTag` looks it up through `SourceIndex` (in `Attacks` or `PlayerAbilities`).
- Attack: on the `Attack` event (windup start) the subsystem passes the tag and the windup in simulation seconds (`WindupTicks / TickRate`). The actor plays the montage at the rate that puts its first notify named `Impact` at the end of the windup (`GetPlayRateForImpact`, clamped; rate 1 without a notify or windup). Without a montage the body lunges, as before.
- Every frame `SetAnimationState(|Velocity|, rate)`: `Speed` for locomotion, and `GlobalAnimRateScale` = the fight's time scale (0 while paused), so animations follow pause and the speed buttons. Idle breaks play after a random interval (animation time) of standing still without a montage, from a stream seeded like the look. Turning uses `TurnRate` in animation time.
- Hit: `Anim.Hit`, unless an attack montage plays or the unit is dead. Death: the widgets, selection ring and move marker hide at once, `UCombatAnimInstance::PlayDeath` plays `Anim.Death` and pauses it just before it would blend out (the last pose stays), and the actor is hidden after the montage length + `CorpseDuration`. Without a death montage the actor hides at once with the "X", as before.
- Mixamo animations: `Scripts/ImportMixamoAnimations.py` imports every FBX under `D:/Unreal/Assets/Animations` as an animation on `SKEL_Mixamo` into `/Game/Characters/Animations/Mixamo/<subfolder>`, retargets them in one batch (`IKRetargetBatchOperation`, retargeter `Heroes/RTG_AutoGenerated`, `SKM_Mixamo` -> `SKM_Hero_Male`) and moves the results to `/Game/Characters/Animations/Heroes/<subfolder>` (files at the top level: `Heroes/Combat`), named after the file (cleaned, plus `ALIASES`), root motion off. Existing results are skipped. It switches FBX import to the classic importer (`Interchange.FeatureFlags.Import.FBX 0`) so the `FbxImportUI` settings apply, and logs animations that are not in place. The characters' skeleton is `/Game/Characters/Animations/Heroes/SKEL_Hero` (the Fab pack's child skeleton, moved).
- Facing (`UpdateActors`, presentation only): a unit faces its target while it stands or steers straight at it (`SteerPoint` = the target's position), else the point it steers to (route or move order), else it keeps its facing. So a push by separation shows as a step sideways or backwards instead of a turn.
- `ACombatAnimPreview` (placed in a map; ticks in the editor viewport, `ShouldTickIfViewportsOnly`, so no PIE is needed): transient `ACombatUnitActor`s (hidden from the outliner, never saved) for `UnitTypes` (row names of the unit table, a dropdown; empty = all), side by side along its Y axis (`Spacing`), walking its X axis back and forth over `PathLength` at their `MoveSpeed` (or `SpeedOverride`), standing `StopTime` at each end (already facing back, so they turn while standing). `bCycleDirections` (default on) changes the direction every leg while keeping the facing between a leg and the way back: out forward, back backwards, out to the right, back to the left (`GetFacingOffset`, the leg count per figure); off, `FacingOffset` turns the figures away from their path so the walk always goes that way seen from them (90 = to their right, -90 left, 180 backwards), for tuning one strafe sample. `TimeScale` and `bPaused` act like the panel's speed buttons. The row's `MoveSpeed` and `LocomotionRate` are read from the unit table every frame; Rebuild (a Details button, also on a change of `UnitTypes` or `Seed`) spawns the figures again after a look changed. In the editor world the body gets `SetUpdateAnimationInEditor`, and `UCombatMeshMergeCache` also runs in editor worlds.
- The script also creates `/Game/Characters/Animations/DA_AnimSet_Child` (locomotion `BS_Child_Idle_Run`, idle breaks `AM_Child_IdleLookAround/WaveHello/IdleLookPhone`, montages made from the pack's sequences) and sets `ABP_Combat` as its AnimClass once that AnimBP exists.
- LevelDesigner previews also show the look (and its idle locomotion), with the look seed of the last fight's seed and the preview's unit ID, so start units look as in a fight with that seed. The first facing is set at once, also for animated figures (`bHasFacing`); after that they turn at `TurnRate`.

The control panel is at the top left of the game viewport, inside a full-screen box that lets clicks elsewhere through. It shows the mouse cursor and sets input to Game+UI, so the console still works.
- Panel controls (built in code, English labels):
  - Level: the name of the LevelDesigner level (`GetDesignLevel`), read only; it is chosen in the LevelDesigner. When play starts it is `UCombatSettings::DefaultLevel` (`EnsureDesignLevel`, a new empty level if that file is missing). There is no setup choice: `UCombatSetup` fights only come from the console (`Combat.Start/Simulate/Batch <setup>`) and the auto-start.
  - Seed field and a Random seed button.
  - Start / Restart (`PlayDesignLevel`: the LevelDesigner level as it is, saved or not), Stop, Pause/Resume, Walls (Up / Cutaway / Down, V) and Reset camera (F).
  - Waves (only for a fight with waves): `GetWaveText()` and a **Call wave** button (disabled when `CanCallWave()` is false).
  - Speed 0.05× / 0.1× / 0.25× / 0.5× / 1× / 2× / 4×.
  - Debug Off / Targets / + Distance map, which sets the `Combat.Debug` console variable.
  - Show "Taunt range", which toggles `Combat.ShowRanges`.
  - Replay: Save, a dropdown of the replay files (refreshed when opened, newest first), and Play. The status line shows "Replay: ..." and the verdict.
  - Batch: 100 / 1000 on the LevelDesigner level (seeds start at the seed field; the screen freezes during the run) and a CSV toggle. The summary appears below the status line.
  - Taunt: "Asset" or a slider of 1–10 m in steps of 0.5 m. It sets `UCombatSubsystem::SetTauntRangeOverride`, which `StartFight` applies to every Taunt skill before the simulation is created, so it takes effect at the next Start and a running fight never changes. `Combat.Simulate` does not use the override; it always uses the asset.
  - A status line with the level, seed, tick and running/paused, or after the fight the outcome and checksum.
- The active speed and debug level are tinted green. Nothing is saved: the panel starts from the defaults each time.

### Player input (`SCombatUnitList`, `ACombatPlayerController`)

- `ACombatHUD` also shows `SCombatUnitList` at the top right. It has one row per unit of `PlayerTeam`, with the name, a small health bar, the status labels and the order text (`GetOrderText`: "Queued: ..." during the command delay, "Moving to (x,y)", "Dead").
  - The name is the row's `DisplayName` (or the row name), numbered when a type appears more than once.
  - Dead units stay as grey, disabled rows.
  - The list rebuilds when `GetFightSerial()` changes (start/stop); health and labels update every frame.
- Clicking a row selects the unit, or deselects it if it was already selected. Under the row its actions appear:
  - **Move**: `BeginMoveTargeting`; the button turns orange until the next arena click.
  - One button per player ability (`GetAbilityName`: the ability's `DisplayName`, or the last part of its type), which sends an `Ability` command.
- `ACombatPlayerController` (set by `ACombatGameMode`):
  - It turns the mouse into a point on the grid plane (deproject plus a plane intersection, no collision needed).
  - Left click goes to `HandleArenaClick` on release (with the point where the button went down), so pressing the right button as well can still turn it into a camera pan. While targeting it sends a `Move` command to the clicked cell; otherwise it selects the nearest own living unit within its radius + 30 cm, or deselects.
  - Right click goes to `HandleArenaCancel` (cancel targeting, else deselect) on release, if the mouse moved less than `CameraDragThreshold` pixels; otherwise it was a camera drag. Esc is not used, because it ends PIE.
  - Clicks on the HUD panels go to the UI (also the wheel over a list).
- Free camera (`ACombatPlayerController`, like the editor viewport; presentation only). It moves the view target camera (`UCombatSubsystem::GetArenaCamera`, which first remembers its placed transform):
  - Right drag: look around; while held WASD fly, Q/E down/up, Shift ×`CameraFastMultiplier`, and the wheel scales the fly speed (×1.25 per step, 0.1–10).
  - Middle drag: pan; the grid-plane point under the cursor stays under it.
  - Left + right drag (either pressed first): like the editor, mouse X moves along the camera's right axis and mouse Y along world Z (up/down), one `CameraZoomStep` of the distance to the grid plane per 10 pixels. It stops painting, erasing, a pending click or a look drag, and ends when either button is released; no click or cancel follows.
  - Wheel: zoom along the cursor ray by `CameraZoomStep` of the distance to the grid plane (out by the inverse, so in + out cancel).
  - Alt + left drag: orbit around the grid point where the drag began (`CombatCamera::Orbit`). Alt + right drag: dolly, one zoom step per 10 pixels.
  - F (and **Reset camera** on the control panel): `ResetCameraToOverview`.
  - Look, orbit and dolly put the cursor back at the drag start every frame, so a drag never reaches the screen edge. Releases are checked with `IsInputKeyDown`, because a release over the HUD never reaches the game.
  - LevelDesigner edit mode has the same camera controls; there a right click erases a cell instead of cancelling, and erase strokes are Shift + left drag.
  - After every move `CombatCamera::Clamp` keeps the camera inside `GetCameraBounds()` (the shown grid plus `CameraBoundsMargin`, `CameraMinHeight`–`CameraMaxHeight` above it) and the pitch within `CameraMinPitch`–`CameraMaxPitch` (default -90 to 0). The speeds use the frame time, so pause and the speed buttons do not affect them.
- Selection is presentation state in the subsystem (`SelectedUnitId`, `bAwaitingMoveTarget`). A selected unit that dies is deselected. Everything reaches the fight only through `IssueCommand`.
- `ACombatUnitActor`:
  - `SetSelected` shows a ring of `SelectionRingSegments` (16) flat engine cubes around the feet (`SelectionRingOffset` from the edge).
  - `SetMoveTarget` shows a flat disc on the target cell and a thin bar from the unit to it while a move order runs.
  - These use the shape material in 1.5× the team color, are placed in world space, and are visible in release builds.

### Presentation (`ACombatProjectileActor`)

- A small engine sphere (`Diameter`) at `FlightHeight` in the team color (`BasicShapeMaterial`), facing the flight direction. No collision, no shadow.

### Data and settings

- **Units and skills** (`CombatUnitData.h`) are rows of two DataTables, `/Game/Data/DT_Units` (`FCombatUnitRow`) and `DT_Skills` (`FCombatSkillRow`), set in Project Settings > Game > Combat > Units (`UnitTable`, `SkillTable`). Their source is `Data/Units.json` and `Data/Skills.json` in the repo (the DataTable JSON format, the same as the editor's Export as JSON; tags are `{"TagName": ...}` objects, `ParentTags` are filled in on import and may stay empty). `Scripts/ImportCombatData.py` fills the tables from the files (it first checks that every skill a unit names exists); with the argument `export` it writes the tables back to the files after editing in the editor.
  - `FCombatSkillRow`: `DisplayName`, `Type` (`ECombatSkillType` in `CombatTypes.h`: `Melee`, `Ranged`, `AoE`, `Taunt`; `None` is not used; the simulation stats keep it as `FCombatAttackStats::Type`), `bPlayerActivated` (off = the AI uses it, on = only the player triggers it, without cooldown or windup), range, cooldown, windup, `Recovery` (seconds standing still after the hit or shot; with the unit's cooldown multiplier), damage, `ThreatMultiplier`, `Effects` (`FCombatEffectDefinition`: effect tag, duration in seconds, stacking, max stacks, granted and blocked-by tags, the three multipliers), `ImpactCue`, for ranged `ProjectileSpeed` and `bRequiresLineOfSight`, for AoE `AreaShape`, `AreaRadius`, `ConeAngle` and `TelegraphDelay`, `bAffectsEnemies`/`bAffectsAllies`, and as presentation `AnimationTag` and `ProjectileActorClass` (soft).
  - `FCombatUnitRow`: `DisplayName`, HP, speed (cm/s), radius, innate `Tags`, `Skills` (skill row names, a dropdown via `UCombatSettings::GetSkillRowNames`; several units can own one skill), the multipliers `SkillDamageMultiplier`, `SkillRangeMultiplier` (range and area radius), `SkillCooldownMultiplier` (cooldown, windup and recovery) and `EffectDurationMultiplier` for all its skills, and as presentation `ActorClass` (soft), `Look` and `LocomotionRate`.
  - `FCombatUnitType` is a unit resolved for use: its row and its skill rows split into `Attacks` and `PlayerAbilities`, each in the order of `Skills` (`FCombatAttackStats::SourceIndex` indexes them; `Combat.Ability <unit> <index>` counts the player's). `ToSimStats` applies the multipliers and keeps the skills with a type (not `None`) (player abilities keep their index even when unusable). Melee needs a walking line, and ranged needs sight if required. Taunt becomes `CircleAroundSelf` with `AreaRadius` = `Range`. AoE takes `AreaShape`, `AreaRadius`, `ConeAngle` (full angle, stored as the cosine of half of it) and `TelegraphDelay`; it needs sight with `bRequiresLineOfSight` and a walking line without it.
  - `FCombatUnitCatalog` holds unit and skill rows by name (`TMap`s, only looked up by key): `AddFromTables` copies a unit and its skills from the tables, `Resolve` makes the `FCombatUnitType` (null with the reason when the unit or a skill is missing). Replays store the catalog of their fight. `CombatUnits::FindType` resolves a type straight from the project's tables (LevelDesigner previews and ghost, AnimPreview), `GetAllTypeNames` lists the unit rows.
- Native tags (`CombatTags`) are `Status.Taunted`, `Effect.Taunt/Slow/Rally`, `Cue.Fire/Cleave/Rally/Taunt` and the `Anim.*` actions (see Character animation).
- The skills (`Data/Skills.json`, one row per kind since 2026-10-07): **Punch** (melee, 50 cm, 1 s, windup 0.2 s, 10 damage, `Anim.Punch`), **Taunt** (the AI's, 6 m, 6 s cooldown, applies `Effect.Taunt` → `Status.Taunted` for 4 s), **Shout** (the player's taunt, 4 m, 3 s), **QuickShot** (ranged, 4 m, 3 s, 14 damage), **Cleave** (a 100° cone, 1.6 m), **Fireball** (on the target: 1.5 m radius, 0.6 s telegraph, a slow of ×0.5 for 2 s) and **Rally** (an allies-only aura of 4 m: ×1.25 damage for 3 s).
- The units (`Data/Units.json`, rows named like the former `DA_*` assets without the prefix) and their multipliers (damage / range / cooldown / effect duration; 1 unless given): Krijger (Punch, Shout; 1.2 / 0.8 / 0.8), Tank (Punch, Taunt, Shout; 1.2 / 1 / 1.2), Brute (Punch; 3 / 1.6 / 1.6), Boogschutter (QuickShot, Punch), Magier (Fireball, Punch), Vaandeldrager (Rally, Punch), Bijlman (Cleave), Doelpop (stands still, no skills). `/Game/Data/DA_CueTable` (debug colors for the four cues) comes from `Scripts/CreateCueTable.py`, which keeps an existing table (`FORCE_UPDATE` overwrites it).
- `UCombatSettings` (`[/Script/BattleSystem.CombatSettings]` in `DefaultGame.ini`) holds the tick rate, max steps per frame, the hit stagger (`HitStagger`, seconds), fight time limit, max first-attack delay, retarget interval, path lookahead, separation strength, threat decay (`ThreatDecayMode` HalfLife/Linear, with `ThreatHalfLife` or `ThreatDecayPerSecond`, converted to the per-tick factor/amount), threat threshold, threat switch ratio, retarget distance margin, auto-start (off: fights start from the control panel), the wave pause (`WavePauseSeconds`), the free camera (look and fly speed, fast multiplier, zoom step, drag threshold, bounds margin, min/max height and pitch), default level (`DefaultLevel`) and seed, the unit and skill tables (`UnitTable`, `SkillTable`), team colors, status icons, player team, command delay, replay checkpoint interval, the cue table, the area flash duration, and the telegraph, default-area and taunt colors.
- Skill types and look slots are enums (since 2026-10-07; before, the tags `Attack.*` and `Slot.*`). Statuses, effects, cues and animations stay GameplayTags, so new ones are data and their hierarchy works (`BlockedByTags` on a parent, the animation fallback, overrides on a parent tag).
- `ACombatGameMode`: players start as spectators. In `StartPlay`, after all actors have begun play, it auto-starts the default level if enabled (`bAutoStartFight`, off by default).
